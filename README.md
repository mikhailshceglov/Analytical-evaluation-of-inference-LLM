# Ответы на ключевые вопросы

## Проблема

При параллельном инференсе больших языковых моделей увеличение числа одновременных запросов $N$ повышает загрузку GPU, но одновременно заполняет KV-кэш. Длины запросов и повторное использование префиксов меняют момент, после которого пропускная способность перестаёт расти. Поэтому время обработки одного запроса не определяет зависимость пропускной способности от $N$.

## Актуальность

Масштаб нагрузки значителен: согласно [отчёту OpenAI за 2025 год](https://openai.com/business/guides-and-resources/the-state-of-enterprise-ai-2025-report/), более 9000 организаций обработали через API свыше 10 млрд токенов каждая, почти 200 — свыше 1 трлн. По [оценке МЭА](https://www.iea.org/reports/energy-and-ai/energy-demand-from-ai), все центры обработки данных потребили около 415 ТВт·ч электроэнергии в 2024 году; эта оценка относится ко всем ЦОД, а не только к инференсу LLM. Прогноз пропускной способности при заданной нагрузке позволяет обоснованнее выбирать число GPU и предел параллелизма. Значимость управления KV-кэшем для пропускной способности показана в работе [Kwon и соавторов](https://doi.org/10.1145/3600006.3613165).

## Объект исследования

Процесс параллельной обработки запросов к большой языковой модели на GPU.

## Предмет исследования

Пропускная способность этого процесса, измеряемая числом завершённых запросов в секунду (RPS).

## Цель дипломного исследования

Разработать и проверить аналитическую модель зависимости RPS от числа одновременных запросов для Qwen3-0.6B в nano-vLLM на RTX 4070 Laptop с учётом длительности шагов вычисления и ёмкости KV-кэша.

## Цель на текущий семестр

Для статьи количественно оценить точность прогноза RPS на уже собранных независимых сериях S5 и S8 при закрытой нагрузке: после завершения запроса подаётся следующий, так что в системе поддерживается заданное $N$. Определить точность отдельно до насыщения KV-кэша и после него.

## Задачи

1. Зафиксировать для серий S5 и S8 число одновременных запросов, длины входа и выхода, режим кэша и планировщик.
2. Рассчитать прогноз RPS по модели времени шагов и оценке числа запросов, помещающихся в KV-кэш.
3. Сопоставить прогноз с измеренной RPS для каждой экспериментальной точки; вычислить среднюю абсолютную относительную ошибку.
4. Сравнить ошибки до и после насыщения KV-кэша, а также при включённом и выключенном кэше; указать область применимости модели.
